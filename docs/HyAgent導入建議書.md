## 1. 摘要

HyAgent 是一個**可嵌入既有網站、也可獨立使用的多租戶 AI Agent 整合平台**。它讓企業使用者用一句話完成原本需要跨系統、跨表單、翻規章才能完成的工作，並讓管理者以**設定而非改程式**的方式擴充新表單、新整合與新知識範圍。

本建議書的三項核心主張：

1. **以對話取代表單填寫成本** — AI 逐步補齊欄位、自動套用商業規則驗證、摘要確認後才送出，降低填錯與退件。
2. **以設定取代客製開發** — 新增一張表單、更換一個目標系統，不需改動平台核心程式，也不需重寫前端畫面。
3. **以架構承載 AI 風險** — 權限邊界、資料隔離、送出把關與稽核全部由伺服器端強制執行，不依賴提示詞去「說服」模型守規矩。

平台**不取代**企業既有 OA / HR / ERP / CRM / ITSM，而是位於其上的**體驗層與整合編排層**。

## 2. 產品簡介

### 2.1 產品定位

**HyAgent — Universal AI Agent Integration Platform（通用 AI Agent 整合平台）**

- **使用者端**：以自然語言執行跨系統任務、填寫客製化表單、查詢企業知識、產生報告。
- **管理端**：以後台管理租戶、權限、AI 能力、表單、外部系統整合、知識庫、外觀、事件通知、用量與稽核紀錄。

平台**不綁定特定產品、系統或業務領域**；OA 只是首批已驗證的整合情境之一。

### 2.2 核心設計理念

| 理念                   | 說明                                                                | 對客戶的意義                                   |
| ---------------------- | ------------------------------------------------------------------- | ---------------------------------------------- |
| 結構化定義為單一來源   | 一份表單定義同時驅動資料規則、畫面、驗證、AI 對話行為與外部系統對接 | 前後端不會各寫一套規則而失同步；改規則只改一處 |
| 整合以設定描述         | 目標系統、操作、憑證、欄位對應與錯誤處理皆為可設定項目              | 更換目標系統不需重寫程式                       |
| 多租戶為第一層安全邊界 | 資料在租戶層完全隔離，跨租戶一律不可存取                            | 可同時服務多企業、多部門、多品牌               |
| 權限由後端強制         | 畫面隱藏按鈕不構成安全控制；每次操作都重新驗證身分與權限            | AI 越權風險由架構承接，而非由提示詞承諾        |
| 關鍵元件可抽換         | AI 模型、向量檢索、外部系統連接器與資料儲存皆為可替換模組           | 不被單一 AI 廠商或單一基礎設施綁定             |

### 3.2 系統定位

| 層次                    | 組成                                                                             | 角色                                 |
| ----------------------- | -------------------------------------------------------------------------------- | ------------------------------------ |
| 使用者接觸點            | 企業入口網站（嵌入元件）、獨立前台、管理後台                                     | 使用者與管理者的操作介面             |
| 體驗與編排層（HyAgent） | 身分驗證、對話管理、意圖判斷、能力分派、表單引擎、知識檢索、報告產生、權限與稽核 | 平台核心，統一把關所有存取           |

**設計要點**：前端**永不直接連接**後端業務系統，所有存取都經由 HyAgent 統一把關。HyAgent 擁有表單規則、執行 AI 編排、維護對話狀態、執行驗證，再透過連接器與外部系統交換資料。企業既有系統可部署於另一台伺服器甚至內網，三層各自獨立。

### 3.3 表單能力規格（低程式碼）

- 表單以**結構化定義**描述資料規則、畫面呈現、驗證條件、AI 對話行為、版面分組、簽核關卡與外部系統對接，前端依定義**動態產生畫面**，不需為每張表單另寫程式。
- 支援必填、格式與**跨欄位商業規則**驗證（例如起訖日期關係、額度上限、條件必填）。
- 使用者在確認畫面手動修改的欄位，一律回送伺服器重新驗證後才生效，**畫面所見即送出所送**。
- 需明確同意的條款欄位**必須由使用者親自勾選**，AI 不得代為同意。
- 支援附件上傳（單檔上限 10 MB），依整合設定決定傳送檔案資訊或檔案內容。
- 送出前須通過兩道伺服器端把關：**已向使用者呈現完整摘要**，且**使用者於當次明確確認**。
- 表單定義中不保存任何明文密碼、Token 或金鑰，僅參照集中管理的加密憑證。
- 同一張表單可在不同租戶對接不同目標系統。
- 對話生命週期具明確狀態（收集中 → 待確認 → 送出中 → 已送出 / 已取消 / 失敗），狀態可查詢與稽核。

內建的請假單、國內出差報銷、外出登記可作為**範例模板**；客戶可自建 CRM 客戶建檔、ITSM 報修、ERP 採購需求或自訂內部流程表單，**不需新增專屬 AI 模組**。

| 自帶 AI 金鑰         | 客戶可使用自己的 AI 服務帳號與模型；金鑰經驗證後加密保存，查看時遮罩                                                     |

### 3.4.1 MCP 服務串接與現有範例

HyAgent 已支援 MCP（Model Context Protocol）服務串接，由 HyAgent 後端作為 MCP Client，透過 Streamable HTTP 呼叫外部 MCP server 的工具。企業可將既有系統的查詢與操作封裝為 MCP 工具，讓使用者以自然語言完成跨系統任務。

平台管理員可在後台「MCP 服務」登記端點、設定共用或租戶專屬服務、測試連線、重新整理工具清單，以及停用個別工具或要求操作確認。使用者須具備智慧代理使用權限及對應 MCP 服務權限，才能使用該服務；共用服務也須明確授權。

唯讀工具可直接查詢；寫入工具與未明確標示唯讀的工具，須先呈現確認卡片，經使用者確認才執行。工具可提供表格顯示資訊，寫入確認卡片可依工具定義提供欄位編輯。MCP 呼叫納入工具稽核，並以短效簽章憑證傳遞租戶、使用者與權限，供服務端驗證與再次檢查資料存取範圍。

目前程式碼庫提供以下 MCP 服務範例，實際可用服務仍以部署環境的登記、啟用與授權設定為準：

- **門市服務 Demo（store-demo）**：商品查找、庫存與即期品查詢、建立補貨單、促銷活動查詢及優惠券狀態查詢。補貨操作提供確認卡片，可勾選品項、修改數量與選擇日期。
- **會議室範例（rooms）**：查詢會議室空檔與預約會議室，示範查詢後確認寫入的對話流程。
- **自建服務工具包（mcp-kit）**：提供 MCP HTTP 服務、HyAgent 憑證驗證與呼叫者身分取得能力，供企業開發專屬服務。

上述門市與會議室範例使用示範資料，補貨單與預約紀錄儲存在記憶體，重啟後不保留。正式導入須另接企業資料來源與持久化儲存，並驗證服務端權限、操作正確性及例外處理。目前驗證方式為 HyAgent 簽發的 JWT；採用其他驗證方式的第三方 MCP server，須先評估轉接方式。

### 3.6 報告規格

- 由對話意圖觸發，需具備報告權限；同一租戶同時僅執行一份報告工作，避免資源爭用。
- 背景非同步產生，前端顯示進度，不阻塞使用者操作。
- 分章獨立檢索與彙整；**無資料章節明確標示**，全篇查無資料則不產出檔案。
- **數據圖表由結構化資料計算**，不由 AI 自行產生數字；綜合觀察僅能引用已驗證的資料點。
- 可下載格式由服務端決定並回報，預設保存 30 天。
- 使用者僅能存取自己的報告；管理者於後台查詢與下載會留下稽核紀錄。

### 3.8 部署與環境需求

- 三個服務可部署於雲端平台或客戶自有環境，支援容器化部署。
- 需備：HTTPS 網域、企業級關聯式資料庫（含向量檢索能力）、AI 模型服務存取方式（雲端或地端）。
- 大量附件情境可改用物件儲存。
- **所有機密設定僅存於部署平台的環境設定，不進入程式碼庫。**
- 可**整套地端化**：AI 模型與語意檢索皆改用企業自架服務，資料不出機房。

## 4. 資安規劃

### 4.1 設計原則

1. **提示詞不是安全邊界。** 權限一律由伺服器端強制檢查，AI 無法繞過。
2. **前端隱藏不是控制。** 每次操作都重新驗證身分、租戶與權限。
3. **最小揭露。** 越權存取不透露資源是否存在。
4. **預設不公開。** 知識文件未經標記與授權即不可見，不自動公開既有資料。
5. **副作用需明確確認。** 送出表單、發送通知等具外部效果的操作，必須取得使用者明確確認。

### 4.2 身分與存取控制

| 項目             | 規劃                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 正式身分來源     | 採單一登入：宿主網站以**自家私鑰**簽發短效身分憑證，HyAgent 僅持有公鑰驗證。私鑰永不離開客戶環境，客戶可隨時輪替或作廢公鑰並連帶終止既有登入 |
| 憑證短效與防重放 | 身分憑證強制設定有效期限（分鐘級），並具一次性識別碼防止重複使用                                                                             |
| 外部角色不提權   | 由宿主帶入的角色資訊**不作為授權來源**，一律換發一般使用者身分，避免外部系統誤設造成提權                                                     |
| 登入憑證生命週期 | 使用者、管理者與續期憑證採用彼此隔離的驗證條件；續期憑證為單次使用，偵測重用即終止整條登入；租戶刪除或金鑰變更後舊憑證立即失效               |
| 管理後台         | 獨立管理憑證登入，未設定即停用；機器對機器的管理介面另用獨立金鑰，且不得出現於瀏覽器                                                         |
| 帳密登入         | 正式環境預設關閉；關閉時同時終止先前以此方式簽發的憑證。僅供開發與展示使用                                                                   |

### 4.3 多租戶隔離

- 租戶是第一層資料安全邊界，跨租戶資源一律不可讀取或操作。
- 每次請求統一檢查憑證所屬租戶、登入來源與是否已被作廢；歷史對話、報告與表單皆受保護。
- 使用者姓名、部門、代理人與部門授權以**當前租戶的目錄**解析，相同帳號識別碼在不同租戶不共用資料。
- 對外公開的服務窗口使用獨立的權限解析路徑，不會取得任何內部帳號的授權。

### 4.4 權限與資料範圍

- **服務權限與資料範圍分開判斷**：可以使用知識問答，不代表能讀取所有文件。
- 使用者實際權限為多來源聯集（基礎權限、租戶、部門、帳號與能力套餐的聯集），支援群組與個別帳號配置。
- 知識文件以可見性標籤搭配授權設定；**所有檢索路徑**（語意檢索、結構化表格、目錄）一律套用過濾。
- 自動建議問句僅取用對應對象可見的語料；權限變更後舊有快取立即隱藏並重新產生。
- 表單的建立、讀取、編輯、附件、取消與送出，以及 AI 的表單操作，每一次都重新檢查該表單的授權。
- 管理者可**模擬指定使用者執行查詢測試**，並產出權限配置報告驗證設定是否如預期。

### 4.5 機密資料保護

| 對象             | 保護方式                                                               |
| ---------------- | ---------------------------------------------------------------------- |
| 平台金鑰         | 僅保存不可逆雜湊值，原始金鑰只在建立當下顯示一次                       |
| 客戶自帶 AI 金鑰 | 以業界標準對稱加密演算法加密保存，查看時一律遮罩                       |
| 使用者識別資料   | 對話紀錄上的使用者識別碼加密保存；正式環境未設定加密金鑰時拒絕建立對話 |
| 外部系統憑證     | 集中加密保管，表單僅保存參照；敏感值**僅可新增或輪替，不可明文讀回**   |
| 機密設定         | 密碼、簽章密鑰與 AI 金鑰不寫入前端程式包，也不寫入日誌                 |
| 管理回應         | 租戶資料讀取回應不含任何金鑰或 AI 設定                                 |

### 4.6 AI 特有風險控管

| 風險           | 控管措施                                                                         |
| -------------- | -------------------------------------------------------------------------------- |
| AI 越權操作    | 所有工具執行前檢查權限並留下稽核紀錄；把關機制在伺服器端執行，不依賴 AI 自行遵守 |
| 未經授權送出   | 送出需同時滿足「已呈現完整摘要」與「當次明確確認」兩個伺服器端條件               |
| 重複送出       | 送出前先建立唯一性紀錄再呼叫外部系統，服務重啟後仍然有效，避免重複建單           |
| 代替使用者同意 | 需明確同意的欄位必須由使用者親自勾選，系統不將未勾選視為已填                     |
| 虛構企業規定   | 知識問答查無資料須誠實告知；報告內容必以檢索結果為依據，數據由結構化資料計算     |
| 外部資源濫用   | 報告輸出的文件渲染不允許任意存取外部網路                                         |
| 惡意連結       | 表單條款連結僅允許安全的網址格式，於定義驗證階段即擋下                           |

### 4.7 流量保護與濫用防範

- 登入、後台登入、身分交換與憑證續期各自依來源限流，超過即拒絕並回報重試時間；變更帳號、標頭或金鑰不會重置額度。
- 業務操作另有兩層守門：依「租戶＋使用者」的速率限制，以及依租戶的 AI 用量月配額。
- **預設不信任代理標頭**；反向代理部署須明確設定可信代理來源，避免來源偽造或全體訪客被誤判為同一來源。
- 跨來源請求僅允許第一方網域或客戶指定的白名單來源，正式環境不開放任意來源。
- 附件單檔上限 10 MB；大量附件情境改用物件儲存並可加入惡意檔案掃描。

### 4.8 稽核與可追溯

- 管理動作、AI 工具執行與跨使用者的報告下載皆留下稽核紀錄，內容包含操作者、動作、時間、結果與錯誤摘要。
- 稽核紀錄可對應到具體表單、整合目標與外部系統單號，供事後對帳與爭議釐清。
- 正式環境保留稽核全史。
- 建議納入例行監控的指標：認證失敗率、權限拒絕率、限流觸發次數與伺服器錯誤率。

## 5. 使用情境

### 5.1 情境一：嵌入企業入口網站，對話式辦理表單

**現況痛點** — 員工要辦一件事，得先找到系統、找到正確表單、看懂欄位、猜規則，填錯再被退件。

**HyAgent 流程**

1. 管理者建立租戶，設定允許嵌入的網域、外觀樣式與單一登入。
2. 入口網站置入嵌入元件；已登入的員工由宿主系統帶入身分，**免再輸入一次密碼**。
3. 員工說「我下週三下午要請半天特休」，AI 自動抽出欄位、逐步追問缺漏、套用跨欄位商業規則驗證。
4. 欄位齊備後顯示完整摘要；員工可在表單畫面手動修正，修正內容仍經伺服器驗證。
5. 員工明確確認後才送出，取得外部系統單號與狀態，並可同步通知宿主系統後續處理。

**效益** — 不必記得表單在哪、欄位怎麼填；規則在送出前把關，而非事後退件。

### 5.2 情境二：權限感知的企業知識問答

**現況痛點** — 規章散落在共用資料夾、內部網站與各版本 PDF；問人最快，但人不一定有空，答案也不一定一致。反過來說，搜尋一旦全開，機密文件就會外溢。

**HyAgent 流程**

1. 管理者匯入網站來源與文件（支援資料夾批次匯入），建立可見性標籤標註文件，再授權給部門、帳號或能力套餐。
2. 員工以自然語言提問；系統解析其實際權限，**只從該使用者可見的內容**中檢索。
3. 系統評估候選內容後生成回答並標示來源；查無適當資料時誠實告知，不自行補造企業規定。
4. 管理者可模擬特定帳號執行查詢測試，並以權限報告檢查配置是否如預期。

**效益** — 問答自助化，同時把「誰能看到什麼」變成可驗證的設定，而不是口頭約定。

### 5.3 情境三：知識報告產生

**現況痛點** — 主管要一份彙整，承辦人得跨文件抄、跨表格算，做兩天，下次還要再做一次。

**HyAgent 流程**

1. 員工在對話中提出彙整需求；系統確認其具備報告權限，主題不明確時先追問。
2. 建立背景工作，依「排程 → 產生大綱 → 分章彙整」推進，前端顯示進度。
3. 每章獨立檢索知識庫；**數據圖表由結構化資料計算**，無資料章節明確標示，全篇查無資料則不產出檔案。
4. 完成後可下載（Markdown / HTML，環境具備渲染元件時另有 PDF）；使用者只能取用自己的報告，管理者查詢與下載留稽核紀錄。

**效益** — 重複性彙整從「人天」降到「分鐘」，而且數字有可回溯的來源，不是模型編出來的。

### 5.4 情境四：跨系統整合（OA / HR / ERP / CRM / ITSM）

**現況痛點** — 每接一個系統就是一次客製案：改前端、改後端、改流程，時程與費用都不可預期。

**HyAgent 流程**

1. 管理者在後台建立整合設定：目標服務位址、憑證、可執行的操作、欄位與狀態對應，並執行連線測試。
2. 在表單設計器建立或調整表單，指定要對接的整合設定。
3. **不修改平台核心、不改前端畫面**，同一套對話能力即可服務新系統；同一張表單可在不同租戶對接不同目標系統。
4. 各系統回應被正規化為一致的單號、狀態、訊息與導向網址，前端與稽核介面不需為每個系統另寫邏輯。

**效益** — 第二個、第三個系統的接入成本遠低於第一個；整合工作從「開發」轉為「設定與測試」。

### 5.5 情境五：對外公開的 AI 服務窗口

公開服務窗口可置於對外網站，以獨立的訪客權限運作：只檢索明確授權給訪客的內容，建議問句僅取訪客可見範圍，權限一經變更舊有內容立即停用並重新產生。可在不承擔內部資料外洩風險的前提下，把產品與服務諮詢自助化。

### 7.3 驗收基準

一次完整的驗收故事至少應通過：

1. 建立租戶並完成網域、外觀與單一登入設定。
2. 將服務窗口嵌入白名單網站並正常載入。
3. 宿主網站的登入者可免輸入 HyAgent 密碼直接使用。
4. **不修改平台核心程式**，即可建立客製表單、對接測試系統，完成欄位對應與連線測試。
5. 使用者以自然語言完成該表單，可修改欄位、檢視摘要、明確確認並成功送出，取得外部單號與狀態。
6. 未授權使用者無法使用受限服務，也查不到受限文件。
7. 上傳知識文件並設定可見性後，查詢測試能反映不同帳號的實際可見範圍。
8. 具報告權限者可建立報告、查看進度並下載。
9. 表單送出可觸發具簽章驗證的事件通知。
10. 管理者可查看用量、報告與稽核紀錄，且稽核能對應表單、整合與外部單號。
11. 越權存取、無效憑證、未允許的來源與超出配額，皆被伺服器端拒絕並回報明確錯誤。

12. 如採用 MCP，完成連線與工具清單測試；未授權帳號無法使用服務，寫入操作須先確認，取消時不執行，成功與失敗皆可追查工具稽核。

### 7.4 導入前需共同確認事項

以下項目與客戶環境高度相關，建議於導入啟動會議一併確認，避免後續變更：

### 7.5 AI 使用建議：雲端與地端

HyAgent 的 AI 模型為可替換模組，可採雲端 AI 服務（平台設定或客戶自帶帳號），或企業自架的地端模型。兩者各有取捨，建議依資料敏感度、回答品質需求、預算與維運能力選擇：

| 比較面向   | 雲端 AI 服務                                                   | 地端自架模型                                           |
| ---------- | -------------------------------------------------------------- | ------------------------------------------------------ |
| 資料流向   | 對話內容與檢索到的知識片段會傳送至雲端服務商處理               | 資料不出機房，且不會回退至雲端                         |
| 回答品質   | 可使用最新主流大型語言模型，理解、推理與長文彙整能力較佳       | 受限於可部署的模型規模，複雜推理與長篇報告品質通常較弱 |
| 導入速度   | 取得服務帳號與金鑰即可啟用，適合快速試辦                       | 需準備 GPU 伺服器、部署模型並完成效能調校，建置期較長  |
| 成本結構   | 依用量計費，初期投入低；用量成長時費用隨之增加                 | 前期硬體投入高；用量大時單位成本較低且可預期           |
| 維運責任   | 由服務商負責模型更新與服務可用性                               | 由客戶負責硬體、模型版本更新與服務可用性               |
| 帳號與金鑰 | 可採客戶自帶帳號，金鑰加密保存、查看時遮罩，用量依金鑰來源歸戶 | 不需外部 AI 帳號，無第三方金鑰管理問題                 |

**選擇建議**

1. **適合採用雲端** — 知識內容以一般內部資料為主、希望快速上線並重視回答品質，且企業資安政策允許資料經雲端服務處理。
2. **適合採用地端** — 涉及個資、機密營業資料或受法規限制不得外傳（如金融、醫療、公部門），或企業政策明定資料不得離開機房。
3. **選用雲端時** — 優先選擇具企業級資料保護條款的服務（不以客戶資料訓練模型、資料保存期限明確、可指定處理區域）；建議採客戶自帶帳號，便於自行管理合約、費用與金鑰輪替。
4. **選用地端時** — 先以試辦情境實測模型的中文理解、欄位抽取正確率與回應速度，再決定硬體規模，並預留模型更新與效能調校的維運人力。
5. **可先雲端試辦、再轉地端** — AI 模型為可替換模組，可先以雲端完成功能驗證與流程調整，再視需要切換為地端，不需改動表單與整合設定。
6. **兩種方式共通** — 權限檢查、資料隔離與送出把關皆由伺服器端執行，不因模型來源而改變；建議皆設定 AI 用量配額，並定期檢視欄位抽取正確率與問答無結果率。
