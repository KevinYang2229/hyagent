# 角色與 Agent Skill 初版

角色能力是具名 Scope 集合，用來分配權限；Agent Skill 是既有 serviceRegistry 的任務能力。本版沿用角色，不新增角色資料表或第二套授權。

## 操作

1. 後台進入租戶 →「權限」分組的「角色與授權」。
2. 全員通用的服務可直接在最上方「通用服務」一鍵開給所有登入員工（不含網站訪客）；需要再細分時才建立角色。
3. 按「新增角色」，或使用「一般員工」「報告分析員」範本。範本不預授任何表單或知識庫標籤，請另外勾選。
4. 在角色編輯器同時設定「能做什麼」與「給誰」（所有人（含網站訪客）／所有登入員工／部門／個別帳號），按「完成」，最後按頁面底部的「儲存」。編輯草稿不會自行授權。
5. 到「個人權限」選一個人，確認他最後擁有的能力、來自哪個角色，以及有沒有缺漏。
6. 前台對話上方展開「我的助理能力」。權限修改後按「重新整理能力」，即可查看最新角色與可用任務能力；在原對話輸入需求執行。

## 授權語意與範圍

- 個人權限＝套用給所有人、所有登入員工、所屬部門（沒有部門時為「未指定部門」）與直接指派的角色取聯集。移除角色不會撤銷其他來源的授權。
- 網站訪客（公開聊天視窗、免登入訪客）只取得「所有人」與「網站訪客」的角色；「所有人」的角色不可含知識庫標籤或外部服務。
- 角色名稱不會增加主管查團隊、簽核或跨部門資料權限；這些仍需各業務工具實作並驗證。
- 前台 Skill 清單沿用 serviceRegistry.enabledFor 與使用者可見意圖；未授權任何表單時不顯示填表能力。
- 清單只提供能力摘要，不公開其他人的角色、Scope 或憑證；操作仍走原對話服務與工具權限檢查。
- 本版未新增可編輯 Skill 執行指引、SKILL.md 匯入或新的流程引擎，Skill 仍由既有服務實作。
- 不需要資料庫 migration。既有角色資料保持相容；舊的直接授權在權限頁讀取時換算成角色，儲存後改由角色承載。

## API

`GET /api/skills`，需使用者 JWT，租戶依既有 API Key 解析；不接受 query/header 指定其他使用者。回傳 `{ data: { roles, skills } }`（roles 與實際權限同一套規則，含所有人與所有登入員工的角色），設置 `Cache-Control: no-store`，不消耗 LLM 配額。
